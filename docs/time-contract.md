# 시뮬레이션 시간 계약

v0.7.2의 동기 Chaos 설정에 적용한다. 독립 물리 스레드의 120Hz PID 구현과는 별도다.

## 세 가지 시간

| 시계 | 사용하는 기능 | 긴 프레임 처리 |
|---|---|---|
| 엔진 게임 시간 | 공식 경기·준비·정비 타이머, 키보드 조작량·표시 효과 | 엔진이 전달한 게임 Delta를 반영. 일시정지·배속·엔진 자체 제한의 영향을 받으며 절대 벽시계가 아님 |
| Chaos 장면 계산 예산 | 모터 응답·각속도 PID·자율 속도 적분·배터리·IMU·네트 접촉 힘 | `OnPhysScenePreTick`이 전달한 실제 장면 Delta를 공유 |
| 단조 벽시계 | USB/HTTP 신선도·타임아웃·기록 시각 | 화면 정지 중에도 흐르며 게임 배속과 분리 |

프로젝트는 동기 물리와 최대8개·각1/120초 서브스텝을 사용한다. 한 프레임의 물리 예산은
약66.667ms까지다. 100/250ms 프레임에서 나머지 물리 시간은 **버리며 나중에 몰아서
재생하지 않는다**. 경기 타이머를 물리 속도에 맞춰 느리게 돌리지 않는다. 따라서 긴 프레임은
경기에 영향을 주며, 실제 대회용 시간 정확도/성능 보증을 의미하지 않는다.

## 구현과 표시

- 기체의 입력 갱신은 게임 프레임에서 수행하고, 힘 계산은 Chaos 장면 시작 직전 콜백에서 수행한다.
- 제어·모터·전력은 프레임당 한 번 갱신한다. Chaos 내부 서브스텝마다 PID를 갱신하는 방식이 아니다.
- 자이로 각가속도/가속도 유한차분은 이미 진행된 이전 물리 간격을 사용한다.
- 센서 지연 큐와 기체 접촉 시간은 물리 시간을 사용한다. 효과의 시각적 감쇠는 게임 시간을 사용한다.
- 물리 시간 생략이 있으면 HUD에 `PHYSICS LIMITED`와 누적 횟수·생략 시간을 표시한다.
- 엔진 로그의 `IMPERIAL_TIME_LIMIT`에 해당 프레임의 게임/물리 Delta·누적 생략 시간·보류0을 기록한다.
- F6 JSONL의 `timing`에 `game_s`, `physics_budget_s`, `dropped_physics_s`,
  `deferred_physics_s`(항상0), 마지막 Delta·최대 Delta·횟수를 기록한다. 이 장부는 세션 누적이며
  경기 초기화로 지우지 않는다. `aircraft`에는 누적 `flight_model_s`, `sensor_model_s`와
  `battery_consumed_ah`, `battery_current_a`를 추가한다.
- F6의 키 입력 시작/종료 및 프레임 전반부 표본에는 현재 장면이 아직 처리되지 않을 수 있다.
  `timing`은 마지막 장면 시작 시점까지의 장부다. 최상위 `game_s`와 같은 단계의 시계라고 가정하지 않는다.

## 검증 방법과 남은 범위

`Tests/run-time-contract-tests.ps1`은10대 실제 Chaos 강체를 사용해60게임초를 기록한다.
`-Hitches`는 검사 자식 프로세스에서 실제100/250ms 정지를 각각 한 번 주입한다.
`-Official`은10초 준비 이후 수동·DISARM 상태의 공식 경기 시계를 검사한다.
연습 시험은 로컬 자율 HOLD이며 실제 upstream APF 연동 시험은 별도로 수행한다.
`-Packaged -PackageRoot <Windows 폴더>`로 배포 바이너리를 같은 방식으로 검사한다.

장면 예산을 실제 완료된 Chaos solver 시간과 대조하고,10대 모델/센서 누적 시간·배터리
전류 적분·경기 시계·생략 장부·호버 안정성을 함께 확인한다. 기존 실패 기록은 보존한다.
Boxer/HID, OS 포커스, 실제 다른 PC, 독립 고정주기 PID, 비동기 물리·네트워크 시간 배율은
이 검사의 검증 범위가 아니다. 결과 수치는 버전별 검증 기록을 따른다.
