# USB 조종기 설정·연결·보정

현재 Windows 빌드는 **네이티브 WinMM 조이스틱 입력과 게임 내 보정 패널**을 사용합니다. 실행할 때마다 키보드 입력으로 시작합니다. 저장된 보정값이 있어도 조종기가 자동으로 활성화되거나 기체가 자동 ARM되지는 않습니다.

Mode 1·Mode 2 선택은 v0.7.3부터 제공됩니다. 아래 **정밀 스로틀과 전력 제한 안내는 v0.7.4 기준**이며, 새 실행본의 로컬 배포 검사를 통과했습니다. 받을 버전과 공개 여부는 [다운로드 안내](../README.md#download-steps)에서 확인합니다.

## 1. Windows에서 조종기 확인

1. 조종기의 데이터 전송용 USB 포트에 데이터 케이블로 PC를 연결합니다. 기종에 따라 전원을 켜고 **USB Joystick / 게임 컨트롤러 모드**를 선택합니다.
2. Windows의 `joy.cpl`에서 해당 장치를 열고 스틱을 하나씩 움직여 축 값이 실제로 변하는지 확인합니다.
3. 조종기의 모델 출력·믹서와 USB 축 설정을 확인합니다. EdgeTX의 Classic/Advanced 설정에 따라 전달되는 축이 달라질 수 있으므로 채널 순서를 추측해서 적용하지 않습니다. EdgeTX 기종의 설정 예시는 [공식 USB Joystick 매뉴얼](https://manual.edgetx.org/color-radios/model-settings/model-setup/usb-joystick)을 참고합니다. 이 링크는 컬러 화면 매뉴얼이므로 사용 중인 기종·펌웨어에 따라 메뉴 위치와 모양은 다를 수 있습니다.

참고용 과거 시험: 2026-10-26 개발 PC에서 `0416:8258`은 **Archon M1 PRO MAX**, `1209:4F54`는 **Radiomaster Boxer Joystick**으로 확인했습니다. 후자는 당시 WinMM 슬롯1·6축·24버튼이었습니다. 이 ID·축 수·슬롯은 모든 조종기에 적용할 설정값이 아닙니다. WinMM UI의 일반 드라이버 이름만으로 선택하지 말고, 본인 장치의 표시와 실제 스틱 움직임을 확인합니다. `Tests/radio_probe.py`는 읽기 전용 진단 도구이며 보정값을 만들어 넣거나 ARM하지 않습니다. 이후의 실제 보정 결과와 USB 비행 검증 한계는 버전별 검증 기록을 따릅니다.

## 2. 게임에서 장치와 네 축 선택

1. 먼저 선택 기체를 **MANUAL / DISARM** 상태로 전환한 다음 **C** 또는 **RADIO** 버튼으로 `RADIO / USB CONTROLLER` 패널을 엽니다. 패널을 열면 선택 기체가 수동·DISARM 상태로 전환됩니다. 범위 수집 시작과 USB 활성화 버튼도 선택 기체를 수동·DISARM 상태로 전환합니다.
2. **REFRESH**로 연결 장치를 다시 조회하고 처음에는 **장치 카드**를 눌러 직접 선택합니다. **NEXT DEVICE**로 바꿀 수도 있습니다. 한 대만 연결되어 있어도 최초 선택이 필요합니다. 표시된 장치 이름·축 수·`CONNECTED` 상태를 확인합니다. 기본 화면은 상단 STEP 안내와 **MODE 1 / MODE 2** 선택과 **STICK SETUP**을 중심으로 사용합니다.
3. 수동 배정이 필요한 경우 **ADVANCED OPTIONS**를 엽니다. `LIVE STICK AXES`의 X/Y/Z/R/U/V 막대를 보며 스틱을 **하나씩** 움직입니다. 움직임이 확인된 축을 오른쪽의 `ROLL`, `PITCH`, `YAW`, `THROTTLE`에 배정합니다. 각 **AXIS** 버튼은 사용할 수 있는 다음 축으로 바뀝니다. **SIMPLE VIEW**로 기본 화면에 돌아갑니다.
4. 네 채널에는 서로 다른 네 축을 배정합니다. 잘못된 방향은 **NORMAL / INVERTED**로 뒤집습니다. 의도한 입력 방향은 Roll 오른쪽 +, Pitch 전진 +, Yaw 오른쪽 +, Throttle 최저 0·최대 1입니다.
5. Deadzone은 기본 4%이며 **− / +**로 0–25% 범위에서 조절합니다. 스틱 중립 부근의 작은 흔들림을 제거하는 값입니다.

막대 값은 Windows 드라이버 좌표를 장치가 보고한 범위로 나눈 0–1 값입니다. 원시 HID 패킷이나 비행 보정이 완료된 조종값을 뜻하지 않습니다. 축·반전을 바꾸면 기존 보정은 무효가 되고 USB 입력은 비활성화됩니다.

## 3. Mode 1·Mode 2 스틱 안내 보정

**MODE 1**은 오른쪽 세로 스로틀, **MODE 2**는 왼쪽 세로 스로틀입니다. 실제 조종기의 배치에 맞는 버튼을 선택한 뒤 **STICK SETUP / MODE 1** 또는 **STICK SETUP / MODE 2**를 누릅니다. 사용하는 실제 장치를 먼저 선택하고 라이브 축이 움직이는지 확인합니다. 제조사·장치 ID·축 번호를 다른 조종기의 값으로 추측하지 않고 실제 움직임에서 찾습니다.

| 배치 | 왼쪽 좌우 | 왼쪽 위아래 | 오른쪽 좌우 | 오른쪽 위아래 |
|---|---|---|---|---|
| Mode 1 | Yaw | Pitch | Roll | Throttle |
| Mode 2 | Yaw | Throttle | Roll | Pitch |

배치 정의는 [EdgeTX 공식 Radio Setup](https://manual.edgetx.org/bw-radios/radio-settings/radio-setup)의 Mode 표를 참고했습니다. 시뮬레이터의 선택은 보정 안내와 저장 프로필을 설정하며 조종기 본체의 펌웨어·스프링·믹서를 자동으로 변경하지 않습니다. USB 채널 번호는 별도 측정합니다.

모드를 변경하면 USB가 해제되고 선택 모드와 기존 보정 모드가 다를 때 입력 활성화가 차단됩니다. **새 모드로 보정을 완료해 저장**해야 합니다. 수집 중에는 모드를 바꿀 수 없으므로 취소한 뒤 선택합니다. 취소하면 이전 보정의 모드 선택으로 돌아가며, 취소·모드 선택만으로 디스크의 이전 보정을 덮어쓰지 않습니다. 기존에 모드 정보 없이 저장한 프로필은 Mode 2로 읽습니다. 다음 실행에서 모드를 따로 변경하지 않았다면 저장 설정 연결이 저장 당시 모드를 복원합니다. 다른 모드를 명시적으로 고른 상태의 F8 빠른 연결은 차단됩니다. 새 모드로 다시 보정하거나 기존 저장 모드를 선택한 뒤 연결합니다.

1. 다른 스틱은 중립, 스로틀은 최저로 두고 **START THIS STEP** 또는 **Enter**를 누릅니다.
2. 화면에서 지정한 방향만 양 끝까지 움직이고 각 끝에서 1초 유지합니다. 마지막에는 아래 표의 끝을 유지한 채 **CONFIRM HELD END** 또는 **Enter**를 누릅니다. Enter를 쓰면 마우스를 잡기 위해 스틱을 놓을 필요가 없습니다.
3. 한 단계가 끝나면 먼저 스틱을 중립·최저 스로틀로 돌려놓습니다. 다음 단계의 **START THIS STEP**을 누르기 전 움직임은 다음 축의 범위에 포함되지 않습니다.

| 단계 | Mode 1에서 움직일 스틱 | Mode 2에서 움직일 스틱 | 마지막 유지 위치 |
|---|---|---|---|
| Roll | 오른쪽 좌우 | 오른쪽 좌우 | 오른쪽 끝 |
| Pitch | 왼쪽 앞뒤 | 오른쪽 앞뒤 | 앞쪽 끝 |
| Yaw | 왼쪽 좌우 | 왼쪽 좌우 | 오른쪽 끝 |
| Throttle | 오른쪽 위아래 | 왼쪽 위아래 | 맨 아래 |

4. 네 축을 찾은 뒤 Roll/Pitch/Yaw는 중립, 스로틀은 맨 아래로 두고 1초 유지한 다음 **CAPTURE NEUTRAL** 또는 **Enter**를 누릅니다.
5. 표시된 네 축·반전 방향을 검토하고 **CONFIRM & SAVE**를 클릭합니다. 마지막 저장은 Enter로 실행되지 않습니다. 저장 후에도 키보드 모드이며 **ENABLE RADIO**는 별도로 누릅니다.

두 축을 함께 크게 움직였거나 이미 사용한 축을 다시 움직이면 단계가 거부됩니다. **RETRY THIS STEP**은 현재 단계만 다시 수집합니다. 중간 위치를 끝값으로 확인하거나 스틱을 움직이는 중에 확인해도 통과하지 않습니다. 끝값은 최근 안정 구간의 중앙값에서 수집하며 단발성 초기 패킷은 범위로 잡지 않습니다. 이는 드라이버 값의 안정성 검사이며 USB 지연 측정이나 실제 송신기 자체 보정을 대체하지 않습니다.

설정창이 열린 동안 Enter는 스틱 단계 진행에만 사용되고 Space·비행·기체 선택 단축키는 차단됩니다. F5는 검사용 CSV를 계속 내보냅니다. **CLOSE / C / CANCEL SETUP**은 미완료 값을 버리며 이전에 저장된 프로필을 덮어쓰지 않습니다. 연결 손실·장치 기능 변경 시 진행 중 수집은 중단되며 자동 재개하지 않습니다.

## 수동 축 선택을 사용하는 기존 보정

다음 버튼을 순서대로 사용합니다.

1. **1 START RANGE**: 네 스틱 채널을 실제 양 끝까지 천천히 움직입니다. 스로틀도 최저와 최고까지 움직여 전체 이동 범위를 수집합니다. 이 과정에서 기체는 DISARM 상태입니다.
2. **2 CAPTURE RANGE**: 범위 수집을 끝냅니다. 16개 이상의 실제 입력 샘플과 각 배정 축에서 드라이버 전체 범위의 25% 이상 이동이 필요합니다. 이 수치는 최소 검증 조건이며, 보정할 때는 스틱의 전체 이동 범위를 사용합니다. 정지한 축이나 중립값만으로는 완료되지 않습니다.
3. **3 CAPTURE NEUTRAL**: Roll/Pitch/Yaw를 중립에 놓고 스로틀을 물리적 최저점에 둔 뒤 누릅니다. 중립은 측정 범위의 가운데 60% 안에 있어야 하며 반전 적용 후 스로틀 명령이 5% 이하여야 합니다.
4. **4 FINISH & SAVE**: 네 축의 범위·중립·최저 스로틀 확인을 검증하고 장치 프로필을 저장합니다. 상태 메시지가 실패 원인을 표시하면 해당 단계부터 확인합니다.

보정 후 오른쪽 조종값에서 중립 Roll/Pitch/Yaw가 0, 최저 Throttle이 0 부근인지 확인합니다. 축을 하나씩 다시 움직여 방향과 끝값을 확인합니다. 잘못된 배정·반전을 수정했다면 범위 수집부터 다시 진행합니다. 버튼을 반복해서 누르는 것으로 실제 스틱 이동을 대체할 수 없습니다.

## 4. USB 입력 활성화와 ARM

**ENABLE RADIO**는 현재 연결이 정상이고 보정이 유효하며 스로틀이 5% 이하일 때만 USB 조종을 활성화합니다. 활성화 후에도 기체는 DISARM 상태입니다. 패널을 닫고 **Space** 또는 ARM 버튼으로 별도 ARM합니다. 경기 준비 10초·세트 휴식·종료 상태에서는 ARM이 차단되며 연습 상태와 경기 진행 중에만 허용됩니다.

R6 수동 비행은 모든 기체의 **ANGLE** 방식입니다. Roll/Pitch 스틱으로 최대35° 목표 기울기를 조절하며 중립으로 놓으면 수평을 복원합니다. Yaw는 각속도,고도는 스로틀로 직접 조절합니다. 자동 위치 유지가 필요하면 연습 관제의 HOLD 기능을 사용합니다.

**USE KEYBOARD**는 USB 입력을 비활성화하고 선택 기체를 DISARM합니다. 다른 기체를 선택하면 기존 수동 기체도 DISARM됩니다. 조종기 버튼의 ARM 스위치 매핑은 이 버전에 포함하지 않았으며 ARM은 게임의 Space/버튼으로 수행합니다.

## 선택 사항: DIRECT / PRECISION 스로틀 — v0.7.4

새 사용자 기본값은 **THROTTLE: DIRECT**입니다. 입력 변화에 그대로 대응하는 수동 스로틀을 사용합니다. **THROTTLE: PRECISION**을 선택하면 입력55% 주변에서 작은 스틱 움직임에 따른 명령 변화가 줄어듭니다.55%는 입력 곡선의 기준점이며, 모든 기체·배터리 상태에서 호버하는 출력이라는 뜻은 아닙니다.

1. **모든 수동 기체를 착륙·DISARM**합니다. 다른 수동 기체가 아직 ARM 상태인 경우에도 변경할 수 없습니다.
2. **C / RADIO**로 조종기 설정을 열고 **THROTTLE: DIRECT**를 누릅니다. **THROTTLE: PRECISION**으로 바뀌고 저장 성공 메시지가 표시되는지 확인합니다. 간소·고급 화면 모두 같은 버튼을 사용합니다. 스틱 안내·수동 범위 보정 중에는 설정을 바꿀 수 없습니다.
3. 성공하면 USB 입력이 해제됩니다. **최저 스로틀 → ENABLE RADIO / F8 → 패널 닫기 → 별도 ARM** 순서로 다시 시작합니다. 키보드 수동 조종에도 이 설정이 적용됩니다.
4. DIRECT로 돌아가려면 다시 착륙·DISARM하고 같은 버튼을 누릅니다. 설정 저장에 실패하면 이전 선택을 유지합니다.

Precision은 입력0%·55%·100%의 출력을 보존하고55% 부근의 기울기를0.65로 줄입니다. 최대 출력 권한은 유지하며 모터 자체의 추력 곡선을 바꾸지 않습니다. 보정 패널의 축과 스로틀 값, USB 활성화·ARM의 최저 스로틀 판정은 **정밀 곡선을 적용하기 전의 보정된 입력**을 사용합니다. 이때 “적용 전 입력”은 원시 USB/HID 패킷을 뜻하지 않습니다.

**ANGLE과 Precision 모두 고도를 자동으로 유지하지 않습니다.** 기울기에서 수평으로 돌아올 때 같은 추력의 수직 성분이 커질 수 있으므로 조종자가 스로틀을 조절합니다. 자율 연습의 AUTO/HOLD/RETURN 제어에는 이 수동 입력 곡선을 적용하지 않습니다.

설정은 `%LOCALAPPDATA%\ImperialWingsSimulator\Saved\Config\PilotControls.json`에 저장합니다. 에디터·명시적 검사 경로에서는 해당 사용자 데이터의 `Config/PilotControls.json`을 사용합니다. 형식은 버전1과 `precision_throttle`의 참/거짓 값이며, 잘못된 형식·지원하지 않는 버전은 시작 시 DIRECT로 처리합니다. 별도 파일인 **`RadioProfile.json`의 장치·Mode 1/2·축·범위·중립 보정은 그대로 유지**합니다. 다음 실행에서 선택은 복원하지만 USB 활성화나 ARM은 복원하지 않습니다.

F6 기록에서 `throttle`은 곡선 적용 전 입력, `throttle_command`는 명령, `precision_throttle`은 해당 수동 기체의 정밀 모드 여부입니다. 작은 움직임의 효과를 비교할 때 동일한 기체·배터리·시작 상태로 비교하고, DIRECT/PRECISION 선택을 함께 기록합니다.

**출력이 줄거나 상승이 둔할 때:** v0.7.4는 배터리 공급 전력과 실제 모터 추력을 연결합니다. 화면의 **POWER LIMITED / THRUST %**는 공급 한도에 따라 추력이 줄었음을, **BATTERY EMPTY / NO MOTOR POWER**는 빈 배터리로 모터 전력이 없음을 뜻합니다. 이때 조종기 축 문제인지 전력 제한인지 F6의 요구·사용 가능·적용 전력을 함께 확인합니다. 배터리·ESC 계수는 실험용이며 실물 성능을 측정해 인증한 모델은 아닙니다.

## 5. 연결 손실과 프로필

- 장치 읽기가 실패하면 즉시 USB 입력을 비활성화하고 입력값을 지웁니다. 마지막 성공 입력이 250 ms를 넘으면 입력을 오래된 값으로 판정합니다. 이는 실제 입력 지연을 측정한 결과가 아니라 구현한 유효기간입니다.
- USB로 조종 중인 기체는 입력 손실·USB 비활성화·유효 보정 손실·게임 포커스 손실 시 DISARM합니다. DISARM 후에는 중력과 충돌이 계속 적용되므로 공중에서 정지하거나 위치가 유지되지는 않습니다.
- 재연결만으로 USB 입력이나 ARM이 재개되지 않습니다. 최저 스로틀에서 **ENABLE RADIO**와 ARM을 다시 수행합니다. 보정 도중 연결이 끊기면 범위 수집을 새로 시작합니다.
- 포터블/패키지는 `%LOCALAPPDATA%/ImperialWingsSimulator/Saved/Config/RadioProfile.json`, 에디터는 프로젝트의 `Saved/Config/RadioProfile.json`에 장치 식별값별로 저장합니다. 명시적 `-ImperialDataDir`은 별도 저장 위치를 사용합니다. 고급 화면의 **SAVE PROFILE / LOAD PROFILE**로 수동 저장·불러오기를 할 수 있으며, 불러오기는 항상 USB 입력을 비활성화합니다.
- 식별값은 WinMM 슬롯, 드라이버가 보고한 이름·제조사/제품 값·범위·기능을 포함합니다. WinMM은 여기서 USB 일련번호를 제공하지 않으므로 동일 모델·동일 기능·동일 슬롯의 다른 실물을 완전히 구분할 수 없습니다. 조종기를 교체했거나 USB/모델 설정을 바꿨다면 실제 축을 다시 확인하고 보정합니다.
- 드라이버 슬롯이나 장치 기능이 바뀌면 기존 프로필과 일치하지 않을 수 있습니다. 잘못된 형식·범위·중복 축·다른 식별값의 프로필은 활성화에 사용하지 않습니다.

## 검증 범위

v0.7.3에서는 Mode 1·Mode 2 보정 수학205개와 실행 UI/JSON20개·입력 안전29개를 확인했습니다. [버전별 검증 기록](verification.md)을 따릅니다. v0.7.4 정밀 스로틀은 독립 입력 수학29개 검사를 통과했으며, 새 실행본의 동작·설정 저장/재시작·새 경로 배포 ZIP 검사도 통과했습니다. [v0.7.4 결과](releases/v0.7.4.md)를 참고합니다. 수학 검사는 실제 조종기 입력이나 비행 감각을 검증한 결과가 아닙니다.

네이티브 입력 코드와 패키지 빌드는 완료했습니다. 독립 MSVC 보정 수학 테스트는 `Tests/run-radio-tests.ps1`에서 **기존 버전의 161개 확인, 실패 0개**입니다. 기존 범위·중립·반전·데드존·연결 손실 검사에,안내 보정의 축 자동 식별·중복/동시 이동 거부·안정 끝값·방향·중립·취소와 시작 중립의 양쪽 범위 검사를 추가했습니다. 이 테스트는 내부 수치 자료를 사용하며 실물 조종기 프로필을 생성하지 않습니다.

사용자의 실제 스틱 조작으로 Roll=X,Pitch=Y,Yaw=V,Throttle=Z,모두 NORMAL을 확인했고6,454개 실제 입력의0–1 범위와 중립·최저 스로틀을 저장했습니다. 중립은X0.499016,Y0.499504,V0.497551,최저Throttle=0이었습니다. 실제 USB 활성화·최저 스로틀 ARM도 확인했습니다. 이어진 비행 기록에서는 포커스 상실로 USB가 해제돼 연속 USB 비행을 완료하지 못했습니다. 케이블 분리·재연결·입력 지연과 기체 반응별 방향 검증은 남아 있습니다. 게임 화면의 버전별 기록은 `docs/verification.md`를 확인합니다.

구현: `Source/ImperialWingsSimulator/ImperialRadioSubsystem.{h,cpp}`, `RadioCalibration.{h,cpp}`, `SoccerDronePawn.cpp`, `ImperialHUD.cpp`.

WinMM 입력은 Microsoft의 [joyGetPosEx](https://learn.microsoft.com/en-us/windows/win32/api/joystickapi/nf-joystickapi-joygetposex), [JOYCAPSW](https://learn.microsoft.com/en-us/windows/win32/api/joystickapi/ns-joystickapi-joycapsw), [joyGetNumDevs](https://learn.microsoft.com/en-us/windows/win32/api/joystickapi/nf-joystickapi-joygetnumdevs) 문서를 기준으로 구현했습니다.


## v0.6 다른 PC용 배포

실행 ZIP에는 보정값을 포함하지 않는다. 새 PC의 첫 실행에서는 간소 조종기 화면이 열리고 장치 카드 또는 NEXT DEVICE로 실제 장치를 고른 후 보정한다. 이후 **CONNECT SAVED RADIO** 또는 **F8**은 유일하게 일치하는 저장 장치를 최저 스로틀에서 연결한다. 보정이 없거나 여러 장치가 일치하면 직접 선택해야 하며 자동 ARM하지 않는다. 설정은 `%LOCALAPPDATA%\ImperialWingsSimulator\Saved\Config\RadioProfile.json`에 저장한다. 설치 폴더 이동·새 버전 압축 해제로 설정이 사라지지 않는다. `EXPORT DEVICE REPORT`는 같은 사용자 데이터의 `Diagnostics`에 실제 장치 목록을 저장한다.

개발 PC와 분리한 한글·공백 경로 및 설치 Python/Git을 제외한 환경에서 첫 실행·실제 Boxer 저장값의 저장/재로딩·재시작 시 키보드/비활성 상태를 검사한다. 실제 다른 PC의 HID 드라이버·GPU·USB 케이블 조합은 해당 PC에서 추가로 확인해야 한다. WinMM이 노출하지 않는 조종기나 네 독립 아날로그 축이 없는 장치는 이 입력 경로로 사용할 수 없다.

## v0.7.4 테스트 피드백 양식

새 배포 ZIP의 압축 해제 폴더에서 **`feedback-form.html`**을 Edge 또는 Chrome으로 엽니다. 실제 버전·ZIP 이름·조종기와 Mode 1/2·DIRECT/PRECISION 선택, 재현 순서와 기대/실제 동작을 적습니다. **보고서 미리보기 → 내용 확인란 → TXT 보고서 저장 / JSON 보고서 저장** 후 브라우저 다운로드 목록에서 저장 파일을 확인합니다. 수정한 내용은 다시 미리보기로 확인하며 창을 닫거나 새로고침하기 전에 저장합니다.

이 양식은 오프라인으로 사용하고 게임·조종기 설정을 바꾸거나 보고서를 자동 전송하지 않습니다. 첨부란은 파일 이름·설명 메모이며 파일 자체를 읽거나 포함하지 않습니다. 저장한 보고서와 필요한 화면·F6 기록만 배포자에게 직접 전달합니다. 개인 보정 파일이나 사용자 `Saved` 전체는 전달하지 않습니다. 자세한 절차는 [테스트 결과 보내기](../README.md#feedback-form)를 확인합니다.
