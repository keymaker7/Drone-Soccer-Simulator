한국어·설정 개선에 앞서 G0 기준 보존을 하고, 결과 신뢰성 보완은 해당 변경의 통과를 선언하기 전에 해결한다. 물리·그래픽 개선은 재현과 측정을 선행하며 기본 조종 안정성보다 후순위 기능이 앞서지 않게 한다. 기존 G0~G5와 SC-01~20을 대체하거나 과거 통과를 소급 취소하는 표가 아니다.

이 문서는 사용자 피드백을 반영한 **개발 계획**이다. 기능 구현·Windows 빌드·실물 조종 시험의 완료 기록이 아니다. 현재 공개 실행본은 [v0.7.4-r2 개발 시험판](releases/v0.7.4.md)이며 개발 소스·로컬 시험본·공개 배포본을 구분한다.

기존 [28개 분야·326개 기능](simulator-feature-plan.md)의 번호와 집계를 유지한다. 아래 C01~C16은 같은 기능을 다시 세는 신규 기능 번호가 아니라 **후보 묶음 식별자**다. 기존 구현이 있는 부분은 보강 대상으로, 남은 부분은 후보 또는 미검증으로 기록한다.

## 최우선 피드백과 실행 순서

사용자 피드백: 조종기 설정이 어렵고 한국어 안내가 필요하다. 제품의 기본 방향은 경기장 밖에서 기체를 보는 LOS 드론축구 연습이다.

1. 최신 소스·보정·실행본·검증 기록을 대조한다. 다른 작업의 변경을 덮어쓰지 않는다.
2. **한국어 안내와 간편 조종기 설정을 최우선**으로 개선한다. 기존 Mode 1/2와 개인 보정을 보존한다.
3. 연결 복구·저장 안정성 → 입문 코스·LOS 시야 → 기록·리플레이 → AI·멀티플레이 순으로 검토한다. 안전·제어 결함이 발견되면 해당 결함을 먼저 해결한다.
4. 큰 변경 묶음마다 아래 검수 관문을 통과한 뒤 다음 단계로 넘어간다. 후보 등록만으로 전부 즉시 구현하지 않는다.

### 간편 조종기 설정 목표

**연결 → 그림과 한국어 안내대로 스틱 움직이기 → 아밍 스위치 지정 → 입력 확인 후 비행**을 기본 흐름으로 설계한다.

- 장치명과 실제 입력 미리 보기로 선택 오류를 줄인다. 미보정 장치나 중복 축은 거부한다.
- 축 번호·수동 반전/데드존·레이트·Expo는 고급 설정으로 분리한다. 현재 배포본의 기능과 아직 검증하지 않은 자유 튜닝을 구분한다.
- 한국어 메뉴·오류·복구 문구를 통일하고 글꼴 누락, 잘림, 화면 배율, 키보드 포커스를 검사한다. 한국어/영어 전환은 같은 언어 지원 항목으로 관리한다.
- 취소·뒤로 가기·재시작·저장 실패 시 기존 보정값을 보존한다. 연결만으로 ARM하지 않는다.
- 높은 스로틀·메뉴 복귀·USB 재연결·눌린 채 유지된 아밍 입력으로 의도치 않게 ARM하지 않도록 검증한다.
- 화면의 제품 명칭은 특정 조종기 이름 대신 **조종기 설정**을 사용한다. 모든 USB 장치 호환을 확인 없이 보장하지 않는다.

| C15 | 공격 진입·수비 위치·득점 후 복귀 팀 훈련 | TRN-05~07, TRN-11, TRN-16 | 기존 역할 훈련 명세 연결. 단계별 과제·중단·설명·재시도 후보 |
| C16 | 같은 PC·LAN·온라인 멀티플레이 | LOC, NET, LOB 분야 | 후속 개발. 10대 배치를 10명 동시 접속으로 표시하지 않음 |

### 첫 비행 안내의 인수 조건 — C04 구체화

후보 수를 늘리지 않고 기존 C04 입문 코스에 다음 기준을 적용한다.

- 연결·보정 확인 → 이륙 → 잠깐 호버 → 전진 → 착륙 → 골대 통과/첫 득점 확인을 한 단계씩 안내한다.
- 한 화면에는 한 가지 행동과 짧은 한국어 문장만 우선 표시한다. 예: “이륙해 봐요”, “잠깐 떠 있어 봐요”, “앞으로 가 봐요”, “착륙해 봐요”.
- 실제 성공 조건을 만족하면 다음 단계로 이동한다. 실패하면 “괜찮아요, 다시 해 봐요”처럼 재시도를 안내하고 실패 이유·안전 상태를 숨기지 않는다. 성공 판정의 높이·시간·거리 허용치는 구현 전 확정한다.
- 연결됨/연결 끊김, ARM/DISARM, 설정 저장 여부를 항상 명확히 구분한다.
- USB 재연결만으로 비행·ARM·훈련을 자동 재개하지 않는다. 스로틀 최저·입력 유효성·보정 상태를 확인하고 사용자가 명시적으로 재개해야 한다.
- 뒤로 가기·중도 종료·실패 반복·재시작에서 단계와 저장 상태가 꼬이지 않는지 실제 화면 및 실물 조작 검사를 구분해 확인한다.

### 추가 음성 피드백 — 기존 후보의 세부 검토 항목

2026-10-27 추가 논의는 아래 **제안 백로그**로 기록한다. C01~C16을 세분화하는 것으로 후보 수나 기존 326개 기능 집계를 늘리지 않으며, 구현·검증 완료를 의미하지 않는다.

| 연결 후보 | 제안 및 검토 조건 |
|---|---|
| C05, C12 | LOS에서 기체 앞/뒤를 구별하기 쉽게 하고 방향 보조는 선택형으로 둔다. 보조 사용 여부를 표시한다. |
| C06 | 한 버튼으로 재시도하되 먼저 DISARM 상태를 확보한다. 리셋만으로 자동 ARM하거나 비행하지 않으며 명시적인 재개 절차를 유지한다. |
| C08 | 연습 종료 화면에는 통과 횟수와 최고 연속 성공을 간단히 요약한다. 중단·미완료와 성공을 혼동하지 않는다. |
| C01 | ARM이 막힌 이유를 한국어로 표시하고 실제 거부 원인과 일치시킨다. 단순한 안내 문구로 안전 검사를 대체하지 않는다. |
| C01, C03 | 스틱 중립에서 입력이 흐르는지 볼 수 있는 중립 드리프트 표시를 검토한다. 입력 이상과 기체의 물리적 이동을 구분한다. |
| C06, C09 | 실패한 골대 접근의 위치·각도를 다시 연습할 수 있게 한다. 안전한 초기 상태와 준비 카운트다운을 거치며 카운트다운 종료만으로 자동 ARM하지 않는다. |
| C04, C13 | 성공 효과음과 음성 안내를 각각 켜고 끄고 음량을 조절할 수 있게 한다. 소리를 꺼도 성공·실패와 안전 상태를 시각적으로 확인할 수 있어야 한다. |
| C08, C09 | 정확도 중심/속도 중심 목표 선택을 검토한다. 평가 기준과 선택한 목표를 표시하고 서로 다른 목표의 기록을 섞지 않는다. |
| C03, C09 | 짧은 훈련 묶음을 저장하고 같은 조건으로 반복하는 기능을 검토한다. 기체·보조·코스·시작 조건의 보존 범위를 명시한다. |
| C08 | 동일 조건의 본인 과거 기록과 비교한다. 조건이 달라지면 이를 표시하고 시뮬레이터 기록이 실기체 실력 향상을 보장한다고 주장하지 않는다. |
| C01, C04, C05 | UI 크기·명암 대비를 조정하고 색만이 아닌 모양·문자도 사용해 상태를 구별한다. 글꼴 잘림과 기체/골대 가림을 함께 검사한다. |
| C05 | 저사양 화질 프리셋과 FPS 표시를 검토한다. 성능 향상 여부를 측정하고 기체·골대 식별성과 훈련에 필요한 시각 정보를 유지한다. |

### 기체 보호 가드·내부 프레임 독립 설계 검토 — C11

한국어 안내·간편 조종기 설정의 최우선 순서는 유지한다. 보호 가드와 내부 프레임의 모델링 개선은 C11에 연결되는 **설계 검토 계획**이며 새 후보 번호를 추가하지 않는다.

- 대상 모델과 부품 명칭을 먼저 확인하고 필요한 길이·원주 등 치수 및 조립·충돌 형상 제약을 정리한다.
- 기존 외형이나 구조를 그대로 재현하는 대신 보호 가드와 내부 프레임 각각의 외관·구조를 독립적으로 설계하는 방향을 검토한다.
- 채택 전 관련 권리의 공식 자료와 적용 범위를 검토한다. 현재 디자인의 위법성, 특정 특허의 등록 여부 또는 침해·비침해 여부는 확인·판정한 것이 아니다.
- 이 항목은 소스·모델 변경이나 물리 검증 완료를 뜻하지 않는다. 모델 변경 시 치수·충돌 형상·기체 식별성·프리셋 물리 조건의 일치 여부를 별도로 검증한다.

## 게임 내 메뉴와 화면 흐름

여러 OS 창이 아니라 게임 안의 화면 전환을 우선 설계한다.

- 시작/메인 메뉴 → 플레이 선택 → 싱글플레이(자유비행·기초 훈련·코스/경기 연습).
- 메인 메뉴에서 조종기 설정, 환경설정(언어·화면·소리), 종료에 접근한다.
- 멀티플레이는 구현·검증 전까지 **준비 중**으로 명확히 표시한다. 사용할 수 없는 버튼으로 입장 가능하다고 오인시키지 않는다.
- 비행 화면 → 일시정지 → 재시작/설정/메인 복귀. 메뉴 진입·복귀의 입력 해제와 ARM 정책을 함께 정의한다.
- 뒤로 가기·닫기·반복 클릭·저장 중 이탈·재연결 후 복귀를 검사한다. 온라인 일시정지는 오프라인 정책과 별개로 설계한다.

연결 기능: SYS-03~09, SYS-11, UX-01, UX-03, UX-10. 화면 계획 등록은 구현 완료가 아니다.

## 골대와 원거리 철망 품질 점검

### 골대 충돌 반응

요구는 **부딪혔을 때 움직임이 둔하므로 반응이 더 분명하게 보였으면 한다**는 것이다. 정지 상태에서 저절로 움직인다는 신고와 구분한다.

현재 공개 설명은 Practice의 제한적 충격 반응과 Match의 고정 지지를 구분한다. 개선 전 충돌 속도·접촉 위치·질량·스프링/감쇠·회전 제한·정착 시간을 같은 조건에서 기록한다. 가시성 개선과 실제 물리 계수 변경을 분리하고, 경기 모드 고정을 임의 해제하거나 근거 없이 과장하지 않는다. 리셋 후 위치·충돌·득점 판정의 일치를 함께 검사한다. **원인 확정과 수정 효과 검증은 아직 완료하지 않았다.**

### 원거리 철망 겹침·이상 무늬

거리·시점·해상도·배율·화질을 기록해 같은 장면을 재현한다. 중복 메시/경계 겹침·깊이 충돌·가는 선의 모아레/앨리어싱·LOD·재질은 **조사 가설**이다. 화면 재현 없이 원인을 확정하지 않는다. 변경 전후의 기체 식별성·네트 충돌 형상·프레임 비용도 대조한다. 연결 기능은 ARN-08, ARN-11, GFX-11, GFX-12 및 COL/QA 분야다.

각 결과는 **통과 / 실패 / 중단 / 미검증**, 실행 버전·환경·재현 순서로 보고한다. 자동 검사가 많아도 실제 조종성을 검증한 것으로 처리하지 않는다. 실물 조작이나 다른 PC가 필요한 검사는 협조와 환경 확보 후 수행한다.

기간은 변경 범위·기존 작업 통합·빌드·실물 검증을 확인한 뒤 재산정한다. 잠정적인 일수나 후보 목록은 보장 일정이 아니다.
