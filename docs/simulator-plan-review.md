# 시뮬레이터 정밀 검토·자체 피드백·실행 계획

## 최신 계획 적용 안내 — 2026-10-28

[최신 정합 점검·보완 검수](practice-candidates-2026-10-27.md#review-2026-10-28)를 이 문서와 함께 적용한다. 한국어 안내·간편 조종기 설정이 최우선이며 안전 결함은 먼저 해결한다. 아래 f05aa66 기준 RV-01~16·WP·SC-01~20과 후속 구현 기록은 역사적 근거로 유지한다. 예전 착수 순서·미구현 설명을 최신 상태로 일괄 해석하거나 과거 검사 수치를 새 실행 결과로 재사용하지 않는다. 기존 326개 기능 번호와 체크 상태는 변경하지 않았다.

검토일: **2026-10-26 KST**. 초기 검토 소스 `a5f817a`, 최종 대조 소스 **`f05aa66`**. v0.6.0 포터블 사전 배포와 기존 v0.5.0 안정 배포를 구분한다.

기존 [전체 기능 명세](simulator-feature-plan.md)의292개를 검토해 **34개를 추가하고16개를 구체화**했다. 현재 관리 범위는 **28개 분야·326개 기능**이다. 이번 결과물은 정적 검토·자료 조사·계획 보완이며 새 코드·새 빌드·실물 비행·온라인 경기 시험을 뜻하지 않는다.

최종 대조 중 v0.6의 F6 JSONL·F8 재연결·장치 진단·사용자별 저장을 확인했다. DAT-03/13·REL-08은 신규 완료 과제로 중복 계산하지 않고 보강으로 표시했다. 최신 [포터블 실행 안내](PORTABLE_QUICK_START.ko.md)와 실행기·설정 저장 경로를 보존한다.

## 자체 평가와 이번 수정

기존 목록은 분야를 폭넓게 다뤘지만, 기능 수에 비해 **경기 공정성의 진입 조건, 판정 순서, 시간 기준, 수치 검수와 출시 경계**가 약했다. 다음과 같이 보완한다.

- 수동 경기에 자율 위치 보조가 들어갈 수 있는 호출 경로를 P0로 올린다.
- 고급 파괴 표현을 기다리지 않고 논리 고장·태그·기권·승계부터 경기 코어를 검수한다.
- 물리 구조를 다 만든 뒤 네트워크를 붙이지 않고 M0에 작은 서버 물리 실험을 둔다.
- 구현 상태와 검증 상태를 분리하고, 수치 초안·미확정 조건·실제 결과를 구분한다.
- 데이터의 분모·누락·확정 판정을 정의한 뒤 경기 개선 통계에 사용한다.
- 공개 방 탐색보다 비공개 원격5대5를 먼저 완성한다.

### 1-1. 기존 설명에서 정정할 규정 조건

[S1의 인쇄9~10쪽](https://dronesoccer.org/static/files/Rule-book-1.pdf)을 대조한 결과, 웹 요약 중심의 기존 설명에 아래 조건이 빠져 있었다.

| 구분 | 정밀화할 내용 | 본 프로젝트에서 유지할 선택 |
|---|---|---|
| 태그 탈락 | 원문은 상대의 Striker 식별 가능 여부를 포함 | 사용자 요청의 엄격 무득점 정책은 별도 명시 |
| 추가 방향 LED | 역할색과 일치하는 색상 조건 | 현재 흰색/빨간색 방향등은 훈련 설계로 보존 |
| 승패 | 1승2무·동률·추가 절차까지 구분 | 단순2선승 표시를 완전한 규정 구현으로 부르지 않음 |
| 태그 장착 | 세부 태그는 대회 기준 확인 필요 | 좌우2개씩은 사용자 지정이며 부분 탈락 기준은 미확정 |

**규칙 우선순위 설계:** 선택 판본 → 해당 대회 예외 → 명시된 사용자 변형을 저장한다. `UserStrictTag`와 공식 식별 판정을 구별하고, 기능 준비 전 공식 적합 인증처럼 표시하지 않는다. 현재 실행 파일의 표시·득점 코드는 이번 문서 변경으로 바뀌지 않았다.

## 3. 신규 요구와 기존 항목의 중복 관리

기존 번호는 유지한다. 새로운 요구는 기존 행과 다른 검수 결과를 요구할 때만 추가했다. 세부 설명이 겹치는 경우 기존 항목의 하위 검수로 연결하고 별도 완료로 중복 계산하지 않는다.

|---|---|---|
| SYS-11 | 세션 설정 묶음·빠른 재시작 | 규정·기체·입력곡선·배터리·난이도·시드를 복원하고 보조 여부 표시 |
| INP-13 | USB 연결 구성 점검표 | 펌웨어/모델·USB 모드·Classic/Advanced와 실제 축을 확인하고 RF 설정 안내의 기종 차이 표시 |

WP-A/B/E를 먼저 진행하고 WP-D는 전체 경기·고급 파괴가 완성되기 전에 작은 실험을 한다. WP-C는 논리 상태로 먼저 검수한다. 사용자에게 출시하는 경기 기능은 전체 판정 연결이 완료된 범위만 표시한다.

### 판정·시간 구조의 설계 초안

- 기체 물리 상태와 경기 역할/자격, 자동 판정 후보와 주심 확정을 분리한다.
- 판정 사건에 `event_id, match_id, set_id, simulation_step, actor_id, role_revision, cause`를 기록한다.
- 같은 순간의 사건은 기준 물리 step과 세부 시각, 규정 우선순위로 정렬한다. 파일에 도착한 순서를 판정 순서로 쓰지 않는다.
- 세트 상태의 후보: `Ready → Playing → SetResultPending → Penalty/Review → SetFinalized → Break/MatchFinished`.
- 실제 허용 시간·판정 절차는 선택 규정으로 정한다. 이 상태 이름이 규정 조항을 대체하지 않는다.
- 주심의 기권/승계·태그 식별 판정과 서버가 처리한 사건의 일치 여부를 검사한다.
- 재접속은 현재 상태를 받는 절차다. 과거 입력 재실행이나 자동 ARM으로 복구하지 않는다.
- 경기 중 임의 정지·되감기·시간 감속·목표점 이동은 허용하지 않는다. 연습과 심판이 승인한 중단 절차를 구분한다.

이 초안은 구현 API 확정이 아니며 현재 UCLASS/API 이름을 임의 변경하라는 지시가 아니다.

## 6. 드론축구 경기에서 개선할 운영·훈련 기능

아래는 **기존 규칙을 임의 개정하는 제안이 아니라**, 선수·코치·심판이 경기 과정을 이해하도록 돕는 제품 개선안이다. 통계의 효과·교육 효과는 아직 현장 검증하지 않았다.

| 골대 접근 효율 | Striker의 접근·반등·재접근 비교 | 연습용 골대 앞1m/폭1.2m 영역 진입 구간과 승인 골의 수. 영역·재진입 여유를 설정에 저장 | 공식 슈팅 통계가 아닌 제품 정의. 분모0이면 계산 불가 |

| 역할별 위치/동선 비교 | Guide/Libero/Sweeper/Keeper의 간격·복귀 연습 | 역할과 시간 구간이 붙은 위치 히트맵·골대 앞 체류·자기 팀 근접 사건 | 위치만으로 올바른 전술이라고 평가하지 않음 |
| 접촉과 고장 복기 | 고장 발생 전 충돌을 검토 | 같은 기체 쌍 접촉을 하나의 사건으로 묶고 충격·발생 전 상태 표시 | 접촉 횟수는 수비 성공·Guide 도움의 확정 수치가 아님 |
| 승계 절차 훈련 | Striker 불능 후 Guide가 절차를 수행 | 선언·조종 중지·접촉·심판 확정까지 순서·누락 확인 | 단순 자동 접촉 횟수를 승계 성공률로 계산하지 않음 |
| 심판 판정 설명 | 무효 득점·오프사이드에 대한 이의 확인 | 후보·최초 판정·확정/정정과 근거 사건을 같은 화면에서 조회 | 자동 판정을 인간 심판의 권한으로 오인하지 않음 |
| 동일 조건 재훈련 | 개인 기록과 기준 비행을 비교 | 규정·기체·입력곡선·배터리·보조·시드가 같은 시도끼리 비교 | 다른 설정/버전의 성적은 별도 집계 |
| 코치의 장면별 피드백 | 팀 회의에서 특정 구간에 메모 | 역할·시각·사건에 메모를 붙이고 개인/팀 과제로 재시도 | 선수 실명·영상 공유는 선택, 자동 공개 금지 |
| 관전자 이해도 개선 | 경기 방송·체험 시 현재 상황 설명 | 승인 득점·복귀 중·승계 대기를 설명하는 전광판 | 선수 화면과 관전 정보의 권한·필요 지연을 구분 |

### 지표를 데이터로 저장할 때의 조건

- 집계마다 `metric_version, rule_profile, config_hash, sample_count, valid_count, missing_count, window`를 남긴다.
- 자동 후보·심판 확정·해석 미정 자료를 분리한다. 미정 자료는 정확도 계산의 정답에서 제외한다.
- Guide 지원·Keeper 기여는 코치/심판 라벨을 먼저 모은다. 임의 가중치의 종합 능력 점수를 먼저 만들지 않는다.
- 통과율·득점률에는 시도 구간 정의와 제외 사유를 함께 표시한다. 의도는 궤적으로 단정하지 않는다.
- 고스트와 전술 오버레이는 충돌·득점에 참여하지 않으며 수동 경쟁 경기의 가려진 정보를 풀어주지 않는다.
- 실기체 훈련 전이는 같은 과제의 전후 비교와 코치 검토로 확인한다. 현재 그런 교육 효과를 입증한 결과는 없다.

## 9. 계획 완료와 기능 완료의 구분

이번 문서 보완의 완료 기준은 근거·자체 지적·기능 번호·검수 시나리오·출시 순서가 서로 연결되는 것이다. 실제 기능의 완료는 아래를 별도로 채워야 한다.

| 기록 필드 | 내용 |
|---|---|
| 구현 상태 | 미착수·설계·구현·통합 |
| 검증 상태 | 미검증·독립 계산·실제 패키지·실물 입력·다른 PC/회선 |
| 근거 | 커밋·빌드 입력·기록 파일·시나리오 번호·측정 조건 |
| 판정 | 통과·실패·중단·해석 보류 |
| 제한 | 미지원 기체·환경·규정·알려진 오차 |
| 후속 | 담당 역할·차기 검수·재현 방법 |

이번에 확인한 정적 경로를 수정 완료로 표시하지 않는다. 최신 v0.6 포터블 사전 배포는 기존 검증 기록을 따르며, 이번 문서 작업에서 새 기능·원문 조건·네트워크·USB 연속 시험을 구현/검증한 새 배포본을 만들지 않았다.
