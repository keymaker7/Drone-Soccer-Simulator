# v0.7.1 — 포커스·메뉴·기체 전환의 키 입력 복구

검토일:2026-10-27 KST. 계획서 CTL-14/INP-10의 입력 복구 경로를 보강했다. [실행 ZIP](https://github.com/sun475300-sudo/Drone-Soccer-Simulator/releases/download/v0.7.1/ImperialWings-Windows-v0.7.1-r1.zip)을 전체 압축 해제하고 `ImperialWingsLauncher.exe`를 실행한다.

## 발견한 문제

v0.7 동작에 시험 액터만 추가한 기준 버전에서, 실제 Unreal 키 바인딩과 Viewport API를 사용해22개 항목 중7개 실패를 재현했다. 포커스 상실 후 수동 ARM·누적 스로틀0.14·모터 명령3.66N이 남았고, 옛 키 반복을 보내면 스로틀이0.25로 증가했다. 메뉴를 닫거나 기체를 선택한 뒤에도 잔류 스로틀0.105가 발생했다. 이 값은 물리 조종기의 측정값이 아니다.

확장 검사에서는 Reset 동작이 키를 지운 뒤에도 이미 계산된 축 콜백이 같은 프레임에 한 번 더 실행되어 스로틀0.002917이 남았다. 해당 프레임의 축 입력과 재ARM도 억제했다.

## 적용한 동작

- GameAndUI에서도 포커스 상실 시 키 상태를 지운다. 수동 기체는 DISARM하고 키보드 누적 스로틀·축 입력을 초기화하며 USB 활성화를 해제한다.
- 입력 초기화 이전 시각의 큐 이벤트와, 새 키 누름 없이 이어지는 비행 키 자동 반복을 차단한다. 복귀만으로 ARM하지 않는다.
- 메뉴·장비 보기·기체 전환·초기화에서도 입력 문맥을 초기화한다. 기존 수동 비행의 일반 추적/전체 카메라 전환은 ARM을 유지한다.
- 메뉴에서 명시적으로 활성화한 USB 연결은 메뉴 닫기와 기체 선택에서 보존한다. 실제 원시 USB 축·중립·범위·반전·저장 보정값은 바꾸지 않는다.
- 명시적인 연습 자율비행은 포커스 상실 뒤에도 힘 기반 비행을 계속한다. 정규 경기의 자율 진입 제한은 유지한다.

## 시험 범위

`Tests/run-input-safety-tests.ps1`는 엔진이 제공하는 **simulated keyboard event**를 사용한다. `UGameViewportClient::LostFocus/ReceivedFocus`, 실제 키 바인딩·스로틀 누적·모터 명령·기체 선택·메뉴/장비 보기·Reset 경로를 검사한다. 정상 실행에서는 이 시험을 만들지 않으며 명시적인 `-ImperialInputSmoke`에서만 동작한다.

초기 수정22개와 확장29개 검사를 통과했다. 확장 검사는 옛 큐 이벤트·GameAndUI·장비 보기와 Reset/ARM 동시 프레임을 포함한다. 최종 Shipping·회귀·ZIP 검사 수치와 입력 지문은 [검증 기록](../verification.md)과 공개 수치 요약에 기록한다.
