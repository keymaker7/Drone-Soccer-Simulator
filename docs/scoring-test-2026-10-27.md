# 득점·오프사이드 경계 검사와 수정

작성일: **2026-10-27 KST**. 대상은 v0.7.4 준비 소스의 [규칙 코어](../Source/ImperialWingsSimulator/DroneSoccerRules.cpp)와 [독립 검사](../Tests/soccer_rules_tests.cpp)다. **수정 후 독립 검사 101개를 통과했으며, 수정된 r2 실행본·ZIP 검사는 진행 중이다.** 수정 전 실행본의 통과 결과를 r2의 최종 검증으로 대체하지 않는다.

## 발견한 문제와 수정 범위

득점 후 팀 전원이 자기 진영으로 복귀했는지 검사할 때, 기체 중심이 정확히 중앙선에서 반경만큼 떨어진 `x = ±0.20m`이면 구형 보호구가 중앙선에 닿아 있다. 이 상태에서는 오프사이드를 해제하지 않아야 한다.

기존 보간 계산 `a + (b - a) × t`의 반올림 오차 때문에 정확한 경계값이 자기 진영 안쪽으로 아주 조금 이동한 값이 될 수 있었다. 그 결과 중앙선에 닿아 있는 동료가 완전히 복귀했다고 판정되어 **오프사이드가 일찍 해제되는 실제 오류**가 재현됐다. 골대 통과 후 점수 증가 자체의 오류와 구분한다.

수정은 양 팀의 복귀 판정에 기존 `Epsilon = 1e-9`를 대칭으로 적용한다. 파란 팀은 `x + 반경 < -Epsilon`, 빨간 팀은 `x - 반경 > Epsilon`일 때만 해당 기체의 복귀를 인정한다. 경계의 수치 잡음은 복귀로 인정하지 않고 명확한 여유가 생겨야 해제한다. 이 허용치는 **미터 단위 계산의 수치 안정화 기준**이며 FIDA가 정한 별도 거리나 육안 심판의 측정 정밀도가 아니다.

규정 근거와 구현 범위는 [FIDA Class40 근거 문서](rules-sources-2026.md) 및 해당 문서가 인용한 [FIDA 공식 규정](https://dronesoccer.org/static/files/Rule-book-1.pdf)을 따른다. 기체 전체의 골대 통과·진영 복귀 정책은 유지했다.

## 독립 검사 결과

검사 실행 방법은 프로젝트 루트에서 `powershell -ExecutionPolicy Bypass -File Tests/run-rules-tests.ps1`이다. 실제 `DroneSoccerRules.cpp`와 검사 코드를 MSVC C++17로 컴파일해 실행한다. Unreal 렌더링·Chaos·USB 입력을 포함하는 시험은 아니다.

| 검사 묶음 | 단언 수 | 주요 조건 |
|---|---:|---|
| 기존 규칙 검사 | 57 | 전체 기체 통과, 골대 경계·반사·역방향, 자격·오프사이드·페널티 수, 시계·세트·무승부·종료 휘슬, 잘못된 입력·초기화, 이동/회전 골대 |
| 양 팀의 모든 포지션 | 30 | 2팀 × 5역할 × 3조건: 해당 팀 득점 자격·상대 점수 불변·오프사이드 자격 |
| 통과 과정 연속성 | 6 | 여유 내 사선 통과, 도중 개구 이탈, 되돌아온 뒤 정상 재진입, 뒤쪽 반복 샘플의 중복 판정 방지, 빨간 팀 첫 관측·오프사이드 재공격 |
| 양 팀의 복귀 경계 | 8 | 팀별 정확한 접촉·`1e-10m` 잡음·`1e-6m` 여유·복귀 후 다음 득점의 4조건 |
| **합계** | **101** | **수정 후 전부 통과** |

기존 57개 검사는 통과했지만 정확한 `±0.20m` 복귀 경계의 보간 오차를 잡지 못했다. 역할·통과·복귀 검사를 확장한 수정 전 실행은 **94번째 단언에서 실패**했다. 출력의 `FAIL after 94 checks`는 앞선 93개를 통과한 뒤 94번째가 실패했다는 뜻이다. 이후 양 팀의 작은 수치 잡음 검사 2개를 포함한 최종 101개를 통과했다.

| 근거 파일 — 개발 PC의 로컬 기록 | 결과 |
|---|---|
| `Saved/Verification/v074-scoring-expanded.log` | `FAIL after 94 checks`: 중앙선에 닿은 동료가 있는데 팀 오프사이드가 해제됨 |
| `Saved/Verification/v074-scoring-fixed.log` | `PASS: 101 FIDA rule checks` |

위 로그는 생성된 검사 자료이며 배포 ZIP이나 공개 저장소에 반드시 포함되는 파일은 아니다. 검사 개수는 독립 단언 수이며 공식 규칙 전체의 준수율을 뜻하지 않는다.

## 실제 Unreal 실행 검사와의 관계

**수정 전 v0.7.4 실행본**은 30·60·120FPS 세 조건 모두에서 `ok=true`, `striker_physical_goal=true`, `blue_score=1`을 기록했다. 열 대를 생성한 경기장에서 파란 Striker가 실제 모터 힘과 Chaos로 골대를 통과하는 연습 시나리오다.

- 근거: `Saved/Verification/runtime-20261027-074208-354/results.json`과 같은 폴더의 `physics-30.json`, `physics-60.json`, `physics-120.json`.
- 당시 빌드 입력 지문: `e0fee06ad8e413bef5dec358aeb01c034eebb54eeccadca9aebffa8d31aa0c91`.
- 자동 검사에서는 명시적 초기 위치 배치 후 자율 목표를 주고, 이후 비행은 모터 힘·물리로 진행한다. USB 조종기나 사람의 수동 경기 시험이 아니다.
- 득점 구간은 `Rules.Reset()`으로 시작하는 **Practice 검사**다. Ready부터 세트 종료까지의 전체 심판 운영을 실제 경기 화면으로 검증한 결과가 아니다.

위 결과는 수정 전 이력으로 보존한다. **수정 후 r2도 30·60·120FPS 모두 통과했다.** 근거는 `Saved/Verification/runtime-20261027-074635-632/results.json`, 최종 입력 지문은 `33e6f4eaed5089dc6a8e71a2c4e0b3cefa7c1d26e6d105616b67c6e9c6b2fe3b`다. 각 조건에서 실제 스트라이커 골대 통과·파랑 1점·빨강 0점·파랑 오프사이드를 검사했다. 공식 경기의 100/250ms 지연 포함 60초 검사에서는 수동·비무장을 유지하고 경기 시계가 60.0123초 진행했다. 새 경로 ZIP 13개와 설정 재실행·전력 검사도 통과했다. [공개 결과](verification/v0.7.4-summary.json). r1은 공개하지 않으며 배포 파일은 `ImperialWings-Windows-v0.7.4-r2.zip`이다.

## 아직 완료하지 않은 범위

가이드의 공격수 승계, 사람의 행위 판정, 경고·카드, 페널티 경기 진행, 연장·승부치기·VAR과 완전한 심판 작업 흐름은 별도 개발·시험 대상이다. 코어의 페널티 **개수** 검사 통과를 실제 페널티 경기 진행의 완료로 표시하지 않는다. 실제 조종기 비행과 다른 PC 검증도 이 독립 검사로 대체하지 않는다.
