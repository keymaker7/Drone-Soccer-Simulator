# v0.7 자율비행 시험과 자체 피드백

검토일:2026-10-27 KST. 계획서 전체의 완료율을 계산하지 않고, 이번에 구현·시험한 범위와 미완료 범위를 나눈다. 실제 Boxer는 사용자가 배터리 부족으로 분리했으므로 이 시험에 USB 입력을 만들거나 재보정을 요구하지 않았다.

## 실제 시험 방법

`Tests/run-autonomy-feedback.py`는 실제 Unreal의10대 Chaos 강체 상태를 원본 SDACS APF에 HTTP로 전송한다. 비행 중 위치를 강제로 바꾸지 않는다. 별도의 수명이 제한된 시험 서버가 귀환 중3.8초 동안503 응답을 반환하여 통신 장애를 재현한다. 시험이 끝나면 자신의 서버와 게임 프로세스를 정리한다. 실제 USB 단절·입력 지연 시험과는 다르다.

순서는 AUTO 출발→18초 자율 훈련→HOLD4초→RETURN→통신 장애→로컬 HOLD→재연결 후 HOLD 유지→명시적 RETURN→10대 착륙/DISARM이다. 마지막으로 정규 경기의 준비 상태에서 AUTO가 거부되고 모든 모터가 정지하는지도 검사한다. 실제 위치·목표점·속도·기울기·가드 상태와 APF 응답 단계를 기록한다.

재현 예:

```powershell
# 개발 환경의 실제 SDACS 원본 경로를 지정한다.
.\.venv\Scripts\python.exe Tests/run-autonomy-feedback.py --repo C:/Path/To/swarm-drone-atc
# Shipping 실행 파일 검사에는 --executable <...Win64-Shipping.exe>를 추가한다.
```

## 발견한 문제와 수정

| 발견 | 실제 관측 | 수정 |
|---|---|---|
| 정면 교차 때 낮은 기체가 바닥 쪽으로 밀림 | 초기 시험의 스트라이커가44cm 부근까지 내려옴 | 양 팀의 훈련 고도를 분리하고, 골대 안쪽에서 상승하도록 경로 단계 추가 |
| 귀환 중 목표 고도 주변에서 진행 정지 | 기존 외부 P 제어의 잔여 오차가 고도 전환 조건을 만족하지 못해125초 안에 전체 착륙 실패 | 자율 속도 제어에±0.8m/s²로 제한한 적분 보상, ARM/DISARM·자율 활성/해제에서 초기화. 전원이 들어온 강체를 활성 상태로 유지 |
| 너무 높은 곳에서 모터 정지 | 이전 귀환은 중심65cm 아래에서 DISARM 가능 | 목표25cm까지 내려오고, 중심28cm·홈 수평20cm·속도0.2m/s 아래에서 DISARM |
| 골대가 설정 질량보다 매우 무거움 | 루트만3kg으로 설정했으나 용접한64개 조각이 더해져 실제93.26kg | 각 원래 강체에 질량을 배분해 합계를 규정 범위12.5kg으로 맞춤 |
| 골대의 좌우 흔들림 | 초안의 자유 진자와 규정의 안정된 지지가 충돌 | 연습에서는 작은 앞뒤 반응만 허용하고, 정규 경기에서는 회전 고정. 실제 골대 좌표계로 득점 검사 |
| 새 기체가 시작하자마자 마모 |35cm 생성 위치에서 바닥으로 떨어져 GUARD99% | 생성 높이를25cm로 낮추고 실제10대가 초기 정착 후100%인지 보기 시험에서 검사 |
| 심판 화면 중앙 기둥 | 실제 Shipping 렌더에서 경기 중앙을 가림 | 심판을 경기장 밖 측면의 비스듬한 위치로 이동하고 실제 렌더 재검토 |
| 기록 파일 동시 접근 | Unreal이 기록을 쓰는 짧은 순간 시험 도구의 읽기가 실패 | 도구가 다음 주기에 다시 읽도록 수정. 입력/기체 데이터는 합성하지 않음 |
| 정규 경기의 자율 진입 우회 | 계획서RV-01/AI-11과 대조하니 HOLD/RETURN과 세트 종료에서 자율 전환 가능 | 명령·기체 API·HTTP 목표 적용에 Practice 제한. 종료 시 자동 귀환 대신 수동 착륙 조종을 유지하고, 정비/종료 단계의 새 ARM은 차단 |

## 해석과 다음 과제

최종 수치는 [v0.7 배포·검증 기록](releases/v0.7.0.md)을 따른다. 목표점 간격1.1m가 실제 기체 간격의 수학적 보장을 뜻하지 않는다. 훈련 경로·고도·환경·부하에 따른 관측값으로 보고한다. 공식 경기는 사람이 LOS로 조종하며 이 APF는 드론축구 전술AI가 아니다.

실제 모터/ESC·질량/관성·항력/후류·보호구 피로 계수의 측정, 여러 PC·HID 장치의 현장 시험, 전체 심판 운영·공격수 승계, 태그 탈락, 멀티플레이·리플레이·코칭은 별도 과제다. [기능 점검표](feature-inventory-2026-10-26.md)와 [전체 계획](simulator-feature-plan.md)에 남겨 둔다.
